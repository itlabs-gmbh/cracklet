Firecracker microVMs on your Mac

Real, unmodified Firecracker on Apple Silicon. A fresh Linux microVM is up about 200 ms after you hit enter and answers SSH in about 3 seconds. One Go binary, open source.

$ cracklet new dev

Needs an M3 or newer, macOS 15+, Homebrew and Go 1.26+. Check with cracklet doctor.

$ go install github.com/itlabs-gmbh/cracklet/cmd/cracklet@latest && cracklet prepare

A microVM in one command

No boot to wait for. cracklet new hands you a running Ubuntu 24.04 with root SSH, its own kernel, disk, IP and hostname.

$ cracklet new dev dev is running at 172.16.1.2 cracklet ssh dev ssh dev.cracklet $ cracklet ssh dev uname -a Linux dev 6.1.186 #1 SMP aarch64 GNU/Linux

A sandbox per agent

Coding agents want root, a package manager and the freedom to run whatever they just wrote. Give each one its own microVM instead of your Mac. Create it per task, let the agent work, throw it away.

Run the agent inside

Start a VM, install your agent CLI over SSH and point it at a repo. It can apt install, run tests and open ports without ever touching your home directory or keychain. Credentials it needs come through the broker below, never as copies.

$ cracklet new task-42 -p 3000

Many agents, side by side

Each VM has its own kernel, filesystem and IP, and the firewall drops traffic between them. Run several agents on different branches at once; none of them can see the others.

$ for n in a b c; do cracklet new agent-$n; done

Execute untrusted code

Let the agent run the script it generated, a dependency you do not trust or a repo you just cloned. The VM only has internet. If anything goes wrong, cracklet rm and start over.

$ ssh task-42.cracklet 'cd app && npm test'

Because every VM is a plain SSH host, anything that speaks SSH works unchanged: VS Code Remote, rsync for the repo, scp for the results, or your agent framework's remote executor. Forwarded ports bring the agent's dev server to localhost on your Mac.

Your credentials stay on the Mac

An agent in a microVM still needs a git push, a Claude login or a browser MCP that only runs on your Mac. Copying tokens into the VM would throw the isolation away. cracklet opens one controlled hole instead: a broker that hands out connections, never secrets.

Grant, don't copy

Store a token once in the macOS Keychain and grant it per VM. The guest only ever holds a placeholder; the broker on your Mac swaps it for the real credential on every request, and only while cracklet ssh is open. Close the terminal, close the hole.

$ cracklet secret set claude-token
$ cracklet grant ai claude github

Default deny, fully audited

Every request is checked against the VM's grants and written to an audit log. GitHub reaches only the repositories your fine-grained token was made for. A denied request is answered with the exact command that would allow it.

$ curl -s :7777/github/acme/app/info/refs {"error":"github is not granted to dev","hint":"cracklet grant dev github"}
$ cracklet revoke ai github

Any tool, one TOML file

The broker knows three primitives: a header-injecting proxy, a bridge for MCP servers that run on your Mac, and an external program. Claude Code and GitHub ship built in. Codex, Gemini CLI or your own MCP server are a capability file in ~/.cracklet/caps, shareable by URL. How it works

$ cracklet cap init codex
$ cracklet cap add https://example.com/gemini.toml

Size it as you need

Defaults are 2 vCPUs, 1 GiB RAM and a 2 GiB disk. Pass --vcpus, --mem and --disk to change them; a bigger disk grows the root filesystem on first boot.

Default

2 vCPUs, 1 GiB RAM, 2 GiB disk.

$ cracklet new

Bigger

4 vCPUs, 2 GiB RAM, 8 GiB disk. The disk grows on first boot.

$ cracklet new dev --vcpus 4 --mem 2048 --disk 8G

Find your microVMs

List every microVM with its state, IP, size, port forwards, grants and the SSH destination to use.

$ cracklet ls
NAME STATE IP VCPUS MEM PORTS GRANTS SSH dev running 172.16.1.2 2 1024M - - ssh dev.cracklet ai running 172.16.2.2 2 1024M 3000 claude ssh ai.cracklet

Stop keeps the disk, start brings it back, rm deletes it.

$ cracklet stop dev
$ cracklet rm dev

Plain ssh, scp, rsync, your IDE

Add one line to ~/.ssh/config and every microVM is reachable as NAME.cracklet. No port forwarding and no sudo needed on macOS.

+ Include ~/.cracklet/ssh_config
$ ssh dev.cracklet

Forward guest ports to localhost on the Mac. Forwards survive stop and start and go away with the VM.

$ cracklet new web -p 8080:80 -p 3000
$ cracklet forward web 5432

Isolated by default

Real Firecracker

The upstream binary, API and CI kernels, untouched. No fork, no patched hypervisor. Firecracker runs on KVM, exactly as it does on Linux.

Internet only

microVMs reach the internet through NAT and nothing else: not each other, not your Mac, not your LAN. Anti-spoofing rules and no IPv6 on the taps close the side doors.

Locked-down processes

Each Firecracker runs in a transient systemd unit with NoNewPrivileges, PrivateTmp, ProtectHome, a device allow-list and a memory cap. A failed create rolls itself back.
