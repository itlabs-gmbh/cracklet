Start with one microVM

Install cracklet, start a Firecracker microVM on your Mac, reach it over SSH and bring its ports to localhost.

Install

cracklet needs an Apple M3 or newer (nested virtualization is an M3 hardware feature), macOS 15 or newer, Homebrew and Go 1.26+. Check a Mac with cracklet doctor.

$ go install github.com/itlabs-gmbh/cracklet/cmd/cracklet@latest
$ cracklet prepare

prepare is a one-time setup of a few minutes and safe to run again. It creates one Lima VM with nested virtualization (4 CPUs, 8 GiB, 40 GiB disk by default), installs the upstream Firecracker binary, downloads the guest kernel and an Ubuntu 24.04 image, verifies all three against pinned SHA-256 digests and writes an SSH key pair to ~/.cracklet. The Lima VM mounts nothing from your Mac.

Create and connect

$ cracklet new dev 
dev is running at 172.16.1.2
  cracklet ssh dev
  ssh dev.cracklet

new does not boot. It restores a golden snapshot: a fully booted VM frozen together with its memory, then gives the clone its own IP, hostname, clock and fresh entropy. The first new for a given size builds that snapshot (about 15 seconds); every later one takes about three. Without a name, VMs are called vm1, vm2 and so on.

$ cracklet ssh dev

You are root in an Ubuntu 24.04 with its own kernel, disk and IP. To use plain ssh, scp, rsync or your IDE, add one line to ~/.ssh/config:

+ Include ~/.cracklet/ssh_config

Then ssh dev.cracklet works from anywhere. It jumps through the Lima VM, so neither port forwarding nor sudo is needed on macOS.

Size and profile

Defaults are 2 vCPUs, 1 GiB RAM and a 2 GiB disk. A disk size other than the profile's image cold-boots instead of restoring the snapshot, and grows the root filesystem on first boot.

$ cracklet new dev --vcpus 4 --mem 2048 --disk 8G

--profile picks the guest image. base is plain Ubuntu; paseo adds Node 22, Claude Code, git, gh and rsync for agent work. Build a profile once with cracklet prepare --profile paseo.

Forward ports

Guest ports appear as localhost:PORT on the Mac. Forwards survive stop and start and go away with the VM. Host ports must be 1024 or higher.

$ cracklet new web -p 8080:80 -p 3000
$ cracklet forward web 5432

cracklet forward web without ports lists them; cracklet unforward web 5432 removes one.

What a microVM can reach

The internet, through NAT, and nothing else: not other microVMs, not your Mac, not your LAN, not services on the Lima VM. Packets with a foreign source address are dropped and IPv6 is off on every tap. The only controlled way back to the Mac is the capability broker.

Troubleshooting

  • Exit code 255 from ssh or exec means the connection failed; check cracklet ls.
  • After a reboot of the Lima VM, microVMs are stopped; cracklet start NAME brings them back.
  • broken in cracklet ls means damaged metadata; cracklet rm NAME cleans it up.
  • Console of a VM: limactl shell cracklet sudo cat /var/lib/cracklet/vms/NAME/console.log
  • Reset everything: limactl delete -f cracklet && rm -rf ~/.cracklet

Before you leave

$ cracklet stop dev

Stop keeps the disk; rm is a separate step. A microVM's disk lives inside the Lima VM, so limactl delete cracklet takes every VM with it.
